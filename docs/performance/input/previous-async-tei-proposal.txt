0. Critical: your three GPU services are almost certainly colliding on the same GPU
Look at your commands:

tei-embedding: NVIDIA_VISIBLE_DEVICES=all, CUDA_VISIBLE_DEVICES=0 → GPU 0
tei-reranker: NVIDIA_VISIBLE_DEVICES=all, CUDA_VISIBLE_DEVICES=0 → GPU 0
gemma4-vllm: NVIDIA_VISIBLE_DEVICES=all, no CUDA_VISIBLE_DEVICES set, --tensor-parallel-size 1
With NVIDIA_VISIBLE_DEVICES=all and no CUDA_VISIBLE_DEVICES restriction, vLLM will default to GPU 0 — the same GPU already hosting both TEI containers. That means under load you have the LLM's KV cache, prefill/decode compute, the embedding model, and the reranker model all fighting over one L4's 24GB and one L4's SM/compute, while your second GPU sits completely idle. This alone can produce exactly the symptom you're seeing (fine at low concurrency, falls over under load).

Fix: pin vLLM to the empty GPU explicitly:

bash
sudo docker run -d --name gemma4-vllm \
    --runtime=nvidia \
    -e NVIDIA_VISIBLE_DEVICES=all \
    -e CUDA_VISIBLE_DEVICES=1 \
    --ipc=host \
    --shm-size=16g \
    -p 8000:8000 \
    -v /root/models/models--google--gemma-4-E4B-it:/app/model \
    -e HF_HUB_OFFLINE=1 \
    vllm/vllm-openai:latest \
    /app/model \
    --tensor-parallel-size 1 \
    --max-model-len 4000 \
    --max-num-seqs 100 \
    --gpu-memory-utilization 0.90 \
    --kv-cache-dtype fp8 \
    --enable-prefix-caching
Since it's now single-GPU, you can also push --gpu-memory-utilization up toward 0.90 (no tensor-parallel coordination overhead to reserve for), which directly increases your KV-cache pool size and therefore how many concurrent sequences/how much context vLLM can actually hold in flight.

Verify with nvidia-smi under load that GPU 0 shows the two TEI processes and GPU 1 shows only vLLM.

PersianHybridSearch.__init__ (in utils/persian_hybrid_search.py) does:

2. The event loop is still being blocked (this is still your #1 latency killer)
This doesn't change with the new deployment. Your /api/query endpoint is async def but everything inside it — agent_service.process_message, rag_system.answer() (using a synchronous openai.OpenAI client), the BM25 build, the (still-local, until you fix #1) embedding encode — is blocking, synchronous Python with no await. With Uvicorn's default single-worker asyncio loop, one slow request freezes every other in-flight request, including health checks. Twenty concurrent requests are processed essentially one-at-a-time, not in parallel — so 20 × (2 vLLM calls + retrieval) easily exceeds 50s per request queued behind it.

Two ways to fix, pick one now:

Quick fix (minutes, no logic changes): change your hot-path route handlers from async def to plain def. Starlette automatically runs synchronous path operations in a thread pool (default 40 threads), so concurrent requests actually run in parallel instead of serializing on the event loop:

python
@app.post("/api/query")
def query_documents(query_req: QueryRequest):   # not async def
    ...
Do this for /api/query, /api/mass-answer, and anywhere agent_service/rag_system is called directly. This is the single highest-ROI change available to you right now given everything else is unchanged.

Proper fix (recommended once TEI migration from #1 is done): switch RAGSystem to AsyncOpenAI and await all three network calls (vLLM, TEI embed, TEI rerank) concurrently with asyncio.gather where independent, and route only the CPU-bound Persian NLP/BM25 work through asyncio.to_thread.

3. BM25 is rebuilt from scratch on every single query
PersianHybridSearch._build_temporary_bm25 fetches every chunk for the allowed documents from Postgres and re-tokenizes/re-stems them with parsivar (pure-Python, slow) on every request — even with the threadpool fix above, this means 20 concurrent requests each burn significant CPU re-tokenizing the same ~900 FAQ chunks repeatedly.

Fix: cache the built BM25 index (and its tokenized corpus) keyed by the allowed_docs tuple, invalidated only when chunks change (e.g., on kb_manager create/update/delete):

python
from functools import lru_cache

class PersianHybridSearch:
    def __init__(self, ...):
        self._bm25_cache: dict[tuple, tuple] = {}  # key -> (bm25, chunk_ids, chunk_dict)

    def _get_or_build_bm25(self, allowed_docs: list[str]):
        key = tuple(sorted(allowed_docs))
        if key not in self._bm25_cache:
            chunk_dict = self._fetch_chunks(allowed_docs)
            self._bm25_cache[key] = (*self._build_temporary_bm25(chunk_dict), chunk_dict)
        return self._bm25_cache[key]
Invalidate the relevant cache entries (or just clear the whole dict) inside kb_manager.py's create/update/delete/revert endpoints after they commit — you already have the document title/id there, so scope it precisely rather than clearing everything.

4. Two sequential vLLM round-trips per query
Query rewrite → then intent classify → then answer generation means every "general" query pays for two full LLM generations back-to-back, serially. With prefix caching now on, the fixed instruction blocks are cheap on repeat, but you're still paying two full network round-trips + decode passes per user turn.

Cheap win: skip the rewrite call entirely when there's no session history (current_summary is empty/"[بدون مکالمه قبلی]") — rewrite_query already checks this and returns early, so verify that's actually hit for first-turn queries in the batch/mass-answer path too (currently mass-answer always calls rewrite_query even with "[بدون مکالمه قبلی]" passed — check that rewrite_query's early-return if not current_summary triggers there; if it's passed as the literal string "[بدون مکالمه قبلی]" rather than empty string, it won't early-return and you're burning a full LLM call for nothing on every batch row).

python
import asyncio
import httpx
# REMOVE: from sentence_transformers import SentenceTransformer

class PersianHybridSearch:
    def __init__(
        self,
        qdrant_client: QdrantClient,
        collection_name: str = os.getenv("QDRANT_COLLECTION"),
        tei_embed_url: str = os.getenv("TEI_EMBED_URL", "http://localhost:7997"),
        use_stemming: bool = True,
        chunk_fetcher=None,
    ):
        self.processor = PersianTextProcessor(use_stemming=use_stemming)
        self.qdrant_client = qdrant_client
        self.collection_name = collection_name
        self.tei_embed_url = tei_embed_url.rstrip("/")
        # One shared, reusable async client — do NOT create a new one per request
        self._http = httpx.AsyncClient(timeout=httpx.Timeout(10.0, connect=3.0))
        self.chunk_fetcher = chunk_fetcher
        self._bm25_cache: dict[tuple, tuple] = {}

    async def _encode_query(self, query: str) -> list[float]:
        resp = await self._http.post(
            f"{self.tei_embed_url}/embed",
            json={"inputs": query, "normalize": True},
        )
        resp.raise_for_status()
        return resp.json()[0]  # TEI returns a batch; we sent one input

    async def _semantic_search(self, query: str, document_names: list, top_k: int) -> dict:
        query_vec = await self._encode_query(query)
        doc_filter = qdrant_models.Filter(
            must=[qdrant_models.FieldCondition(
                key="document", match=qdrant_models.MatchAny(any=document_names)
            )]
        )
        # qdrant-client's sync query_points is a blocking network call — push to a thread
        results = await asyncio.to_thread(
            self.qdrant_client.query_points,
            collection_name=self.collection_name,
            query=query_vec,
            limit=top_k,
            query_filter=doc_filter,
            with_payload=["chunk_id"],
            with_vectors=False,
        )
        return {str(hit.payload["chunk_id"]): hit.score
                for hit in results.points if "chunk_id" in hit.payload}

    def _get_or_build_bm25(self, allowed_docs: list):
        key = tuple(sorted(allowed_docs))
        if key not in self._bm25_cache:
            chunk_dict = self._fetch_chunks(allowed_docs)
            bm25, chunk_ids, _ = self._build_temporary_bm25(chunk_dict)
            self._bm25_cache[key] = (bm25, chunk_ids, chunk_dict)
        return self._bm25_cache[key]

    async def search(self, query: str, top_k: int = 10, rerank: bool = False,
                      allowed_docs: list = None) -> list:
        if not allowed_docs:
            raise ValueError("allowed_docs must be provided for filtered search.")

        expanded_query = self._expand_query_intent(query)

        # CPU-bound Persian NLP + BM25 lookup — off the event loop
        bm25, bm25_chunk_ids, chunk_dict = await asyncio.to_thread(
            self._get_or_build_bm25, allowed_docs
        )
        if not chunk_dict:
            return []
        query_tokens = await asyncio.to_thread(self.processor.process, expanded_query)
        bm25_scores = bm25.get_scores(query_tokens)
        bm25_candidates = sorted(zip(bm25_chunk_ids, bm25_scores), key=lambda x: x[1], reverse=True)[:50]
        bm25_top_ids = [cid for cid, score in bm25_candidates if score > 0]

        semantic_query = await asyncio.to_thread(
            lambda: self.processor.normalize(expanded_query).replace("\u200c", " ")
        )
        semantic_scores_map = await self._semantic_search(semantic_query, allowed_docs, top_k=50)
        semantic_top_ids = list(semantic_scores_map.keys())

        candidate_ids = list(set(bm25_top_ids + semantic_top_ids))
        if not candidate_ids:
            return []

        RRF_K = 60
        hybrid_scores = {}
        for cid in candidate_ids:
            rank_b = bm25_top_ids.index(cid) + 1 if cid in bm25_top_ids else 61
            rank_s = semantic_top_ids.index(cid) + 1 if cid in semantic_top_ids else 61
            hybrid_scores[cid] = {
                "hybrid": (1.0 / (RRF_K + rank_b)) + (1.0 / (RRF_K + rank_s)),
                "bm25": next((s for c, s in bm25_candidates if c == cid), 0.0),
                "semantic": semantic_scores_map.get(cid, 0.0),
            }

        sorted_ids = sorted(hybrid_scores.keys(), key=lambda c: hybrid_scores[c]["hybrid"], reverse=True)[:top_k]
        return [
            SearchResult(
                doc_id=cid, content=chunk_dict[cid]["text"],
                score=round(hybrid_scores[cid]["hybrid"], 6),
                bm25_score=round(hybrid_scores[cid]["bm25"], 6),
                semantic_score=round(hybrid_scores[cid]["semantic"], 6),
                metadata={"document_name": chunk_dict[cid].get("document_name", "")},
            )
            for cid in sorted_ids
        ]

    async def rerank(self, query: str, candidates: list, tei_rerank_url: str) -> list:
        resp = await self._http.post(
            f"{tei_rerank_url}/rerank",
            json={"query": query, "texts": candidates},
        )
        resp.raise_for_status()
        return resp.json()  # [{"index":.., "score":..}, ...] — one batched call, not N forward passes

        probs = torch.softmax(self.classifier(x), dim=1).squeeze()
    class_id = int(torch.argmax(probs).item())
    return {"type": "chitchat", "scenario_id": "chitchat"} if class_id == LABEL_CHITCHAT \
           else {"type": "general", "scenario_id": None}

Why this actually fixes concurrency (vs. the def-not-async def quick fix from before)
The threadpool trick works but caps you at ~40 concurrent in-flight requests (Starlette's default) and each one occupies a whole OS thread just to sit idle waiting on network I/O. With real async/await, a single-threaded event loop can hold hundreds of in-flight requests concurrently, because while one request is awaiting vLLM's or TEI's HTTP response, the event loop is free to advance every other request. This is the difference between "concurrency limited by thread count" and "concurrency limited by actual GPU/network throughput" — which is what you want given your GPUs, not your Python process, are the real ceiling.

Test after this migration: re-run the 20-concurrent-request load test and watch nvidia-smi on both GPUs simultaneously — you should now see both actively utilized, and p95 latency should track vLLM's actual queueing behavior rather than Python-level serialization.
